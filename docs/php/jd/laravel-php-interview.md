# 制造业 PHP 面试题：Laravel 与后端开发（01—30）

本系列按 MES、E-DHR、ERP 对接、OA 流程及 UniApp 岗位 JD 整理，共 180 道题。本篇覆盖后端开发基本功，每题的参考回答都可以先概括，再结合自己的真实项目展开。

::: tip 阅读说明
示例以 PHP 8.x、Laravel 常见能力为背景，具体 API 和默认配置应核对项目版本。所有场景均为面试设计案例，不代表本人已交付的项目经历。
:::

## 一、语言基础与请求处理

### 1. PHP 中 `==` 和 `===` 有什么区别？生产系统为什么要关注？

**参考回答：** `==` 会进行类型转换，`===` 同时比较类型和值。接口中的工单状态、布尔值和数量应先校验并规范类型，再做严格比较，避免字符串、数字和空值被当成同一种含义。不同 PHP 版本的宽松比较细节有差异，不应依赖隐式转换完成业务判断。

**追问要点：** `empty('0')` 为真，`isset()` 无法区分字段不存在和字段值为 `null`。判断是否传入字段可用 `array_key_exists()`，判断必填和数值范围则使用明确的校验规则。

### 2. `null`、空字符串、零和未传字段应该如何区分？

**参考回答：** 它们可能对应“未知”“主动清空”“实际值为零”“本次不修改”四种不同语义。例如更新工艺参数时，未传字段应保持原值，零可能是有效测量值，不能统一过滤为无数据。应在接口契约中写清可空、必填和局部更新规则。

**场景追问：** Laravel 的字符串修剪、空字符串转 `null` 中间件会影响输入，应检查项目配置；`sometimes`、`nullable`、`present` 的使用由业务语义决定，不能互相替代。

### 3. PHP 的值传递、引用和写时复制怎么理解？

**参考回答：** PHP 数组赋值通常使用写时复制，未修改时不必立即复制全部内容；写入后可能产生额外内存开销。引用会让变量共享同一变量容器，不能用来保证并发安全。对象变量持有对象标识，传给方法后修改对象属性会影响同一个对象，但重新给形参赋对象不会自动替换调用方变量。

**追问要点：** `foreach ($rows as &$row)` 结束后要解除残留引用，例如 `unset($row)`。批量导出时应优先减少加载量，而不是滥用引用“优化内存”。

### 4. 接口、抽象类、Trait 分别适合什么场景？

**参考回答：** 接口定义协作契约，例如 ERP 客户端提供发送和查询能力；抽象类适合确有公共流程和可替换步骤的实现；Trait 复用少量横向行为，但容易隐藏依赖和产生方法冲突。对接一家 ERP 时可以先用普通服务类，多实现确实出现时再引入接口。

**追问要点：** 不要为了“可扩展”建立大量空接口和基类。复用必须保留每个供应商不同的鉴权、错误码和重试语义。

### 5. Composer 和 PSR-4 自动加载解决什么问题？

**参考回答：** Composer 管理依赖与版本，PSR-4 约定命名空间到目录的映射，减少手写 `require`。应用项目应提交 `composer.lock`，部署执行 `composer install` 复现依赖，升级依赖才执行 `composer update`。生产环境可按项目要求关闭开发依赖并优化自动加载。

**场景追问：** 本地正常、Linux 找不到类，先查文件名大小写、命名空间、目录映射和部署产物，再重建自动加载；不要直接在生产环境升级所有依赖。

### 6. PHP-FPM、Nginx、Laravel 之间是什么关系？

**参考回答：** Nginx 处理连接和静态资源，并通过 FastCGI 将 PHP 请求交给 PHP-FPM；FPM 的工作进程执行 Laravel 入口文件和请求流程。响应慢要区分连接等待、FPM 队列、应用执行、SQL 和外部调用，不能仅凭“CPU 不高”判断没有容量问题。

**追问要点：** FPM 进程数受单进程内存和总内存约束；增加进程还可能压垮 MySQL。排查结合慢日志、活跃进程、等待队列和下游连接数。

## 二、Laravel 工程实现

### 7. Laravel 的一次请求通常经过哪些环节？

**参考回答：** 从 Web 入口启动应用和服务容器，经中间件、路由匹配、参数与权限校验、控制器、业务服务和数据库，最后生成响应并经过响应中间件。实际启动文件和异常配置位置随版本不同，但认证、授权、规则、事务、输出的职责划分不变。

**场景追问：** 报工接口的参数格式可在 Form Request 校验；工单是否允许报工、是否超量等动态规则应在业务服务中基于当前数据库状态判断。

### 8. 服务容器和服务提供者有什么区别？

**参考回答：** 容器负责依赖解析和对象构建，服务提供者负责向应用注册、启动相关能力。例如把 `ErpClient` 契约绑定到具体实现，再通过构造函数注入同步服务。`register()` 通常注册绑定，`boot()` 用于依赖注册完成后的启动配置。

**追问要点：** `singleton` 的生命周期要结合运行方式判断。常驻进程中不能把当前用户、租户、请求对象存到跨请求复用的单例中，否则可能发生数据串用。

### 9. 控制器、Service、Model 应怎样分工？

**参考回答：** 控制器协调输入输出，Service 表达业务动作与事务边界，Model 表达持久化和关联。报工服务负责检查状态、扣料、更新进度及写审计；控制器不承担这些规则。已有简单 CRUD 不必强制增加 Repository 等多层转发。

**追问要点：** 同一动作可能由 HTTP、队列或定时任务触发，核心规则应复用同一业务入口，避免每条路径复制一套状态判断。

### 10. Form Request 校验通过后，为什么还要校验业务规则？

**参考回答：** Form Request 能验证必填、格式和部分存在性，但校验之后工单或库存仍可能被其他请求修改。关键动态条件必须在事务内通过锁或条件更新再次验证。例如“物料批次存在”并不等于“当前用户可用、未过期、已放行且库存足够”。

**追问要点：** 不能把 `exists` 规则当成数据权限，也不能用请求前的 `unique` 校验替代数据库唯一约束。

### 11. 如何防止批量赋值导致越权？

**参考回答：** 只从已校验数据中提取允许写入的业务字段，并用 `$fillable` 等配置限制批量赋值。工厂 ID、创建人、审核人和放行状态应由服务端身份与业务动作决定，不能接收客户端任意指定。批量赋值保护也不能替代资源授权和字段权限。

**场景追问：** 用户往报工 JSON 加入 `approved_by` 或 `factory_id`，接口应该拒绝或忽略非契约字段，并验证最终记录的归属正确。

### 12. Eloquent 的 N+1 问题如何发现和解决？

**参考回答：** 列表先查询 N 条工单，再逐条访问产品或车间关联，就可能额外执行 N 次查询。可通过查询日志、性能追踪和测试查询数发现，用 `with()` 预加载，计数场景用 `withCount()`，同时限制字段和关联范围。

**追问要点：** 预加载不是越多越好，加载完整物料明细可能耗尽内存。报表可使用聚合查询，并检查关联条件的数据权限。

### 13. Middleware、Gate 和 Policy 应如何选择？

**参考回答：** Middleware 适合认证、限流和请求级约束；Gate 适合相对简单的动作授权；Policy 适合围绕工单、批记录等资源集中管理授权。组织范围和字段权限仍需落到查询及写入逻辑，前端隐藏按钮只改善操作体验。

**场景追问：** 用户能查看 A 工厂，不代表能通过导出接口下载 B 工厂批次；列表、详情、导出、附件和异步任务都要遵守同样的数据范围。

### 14. Event、Listener 和 Job 如何区分？

**参考回答：** Event 表达业务事实，例如报工已确认；Listener 响应该事实；Job 表达可调度执行的工作，例如同步 ERP。监听器既可以同步也可以排队，异步 Job 需要独立考虑重复投递、超时、重试和失败管理。

**追问要点：** 扣料、报工和关键审计若必须一起成功，应在同一本地事务完成，不能依赖异步监听器“最终补齐”本应原子的核心记录。

### 15. 为什么队列任务通常要在数据库事务提交后派发？

**参考回答:** 提交前派发, 消费者可能读不到新记录, 或处理随后被回滚的数据. Laravel 12 可通过队列连接的 `after_commit` 配置或任务的 `afterCommit()` 延后派发; 启用后, 框架等待打开的父级数据库事务提交, 回滚时丢弃事务期间派发的相应任务. 具体仍需核对驱动与连接配置, 不应理解为跨多个独立数据库的原子提交. [L4][L4]

**关键边界：** 提交后派发仍存在“数据库已提交、进程在入队前崩溃”的窗口。必须可靠送达的集成事件，可将 outbox 事件与业务数据同事务保存，再由后台扫描发送。

### 16. 队列的 `timeout`、`retry_after` 和重试次数怎么设置？

**参考回答：** 外部 HTTP 超时应小于任务可用执行时间；worker 的有效超时应小于任务重新可见或被重投的时间，并留清理余量。否则第一次任务尚未停止，第二个 worker 就可能再次执行。SQS 等驱动使用对应的可见性超时，应按驱动核对。

**追问要点：** 重试配置区分网络故障与业务拒绝，使用有限次数和退避。即使配置正确，进程崩溃也会带来重复执行，因此业务幂等必不可少。

### 17. `ShouldBeUnique` 能保证业务绝不重复吗？

**参考回答：** 不能。它利用缓存锁抑制一定范围内的重复任务派发，实际行为受锁期限、缓存共享和任务生命周期影响。业务记录必须使用稳定业务键、数据库唯一约束和事务控制，消费者遇到重复请求返回原结果。

**场景追问：** ERP 已入库但任务响应丢失，唯一任务锁无法证明远端结果；应按原业务键查询远端或安全重发，不生成新入库单号。

### 18. Laravel 中怎样选择事务边界？

**参考回答：** 将必须同时生效的本地写入放在一个事务中，例如报工、扣料、库存流水、审计和 outbox。事务外执行慢速外部调用，避免持锁等待。跨数据库或跨系统的一致性要另做可靠消息、补偿和对账，不能靠一个 `DB::transaction()` 覆盖。

**追问要点：** 死锁重试可能重新执行事务闭包，闭包内不应发送不可撤销的外部请求或重复发通知。失败要保留可定位的异常和业务上下文。

### 19. 多实例部署的定时任务怎样避免重复执行？

**参考回答：** 先明确哪个节点负责调度，再根据部署方式使用 Laravel 的单服务器调度、重叠执行锁或平台调度能力；涉及锁时需使用所有实例共享且支持相应能力的缓存。调度层防重减少重复启动，任务内部仍要按业务键幂等。

**追问要点：** 进程崩溃可能留下未过期锁，应设置合理锁期限并提供受控恢复方式。对账任务要分批、可续跑，避免一次执行阻塞下一周期。

## 三、安全、性能与可维护性

### 20. 数据库更新成功后，缓存怎样保持一致？

**参考回答：** 常见方式是数据库提交后删除相关缓存，读取未命中再回源。删除失败应能重试，缓存要有合理过期时间；并发读写仍可能出现旧值回填窗口，强一致的扣料、放行和权限判断应读取权威数据，必要时使用版本化缓存策略。

**追问要点：** 缓存键应包含工厂、权限范围和规则版本等必要维度，不能让不同组织共享同一份敏感报表结果。

### 21. 异常、日志和接口响应应该怎样统一？

**参考回答：** 区分输入错误、无权限、状态冲突、依赖故障和程序异常，对外返回稳定错误码与可读信息，对内记录关联 ID、业务键、耗时和异常堆栈。未知异常不应被吞掉并转换为“操作成功”，也不能向客户端暴露 SQL、密码或内部路径。

**追问要点：** 已提交但外部同步失败，应返回明确的同步状态，而不是把已发生的本地动作描述成完全失败，引导用户不断重提。

### 22. SQL 注入、XSS、CSRF 应分别怎样防？

**参考回答：** SQL 使用参数绑定，动态排序字段走白名单；XSS 按输出上下文转义，富文本按规则净化；CSRF 针对浏览器自动携带的 Cookie 凭证采用令牌和来源等控制。使用 Bearer Token 的 API 也要防 XSS 窃取令牌和跨域配置错误。

**追问要点：** CORS 不能代替授权；模板转义不能保护任意 JavaScript、URL 上下文；`orderByRaw()` 不能直接拼用户输入。

### 23. 文件上传和下载有哪些关键安全要求？

**参考回答：** 校验大小、类型和内容，使用服务端生成的存储名，将附件放在不可直接执行的存储区。下载时按工厂、批次及角色授权，短期签名链接应控制有效期，敏感附件按要求记录访问。文件路径不能由用户直接拼接。

**场景追问：** 检验报告上传后还应记录摘要、版本和关联业务；压缩包需限制解压规模与路径，避免路径穿越和资源耗尽。

### 24. 大报表导出和长驻队列为什么容易内存增长？

**参考回答：** 一次加载全部数据、保留集合引用、缓存巨大对象以及循环生成文件都可能增加内存。导出按稳定主键分批读取，采用支持流式写出的格式或现有导出库，限制关联加载；长驻 worker 通过生命周期配置回收，并排查持续增长的根因。

**追问要点：** `cursor()` 不代表所有数据库驱动都零缓冲；应实测驱动、ORM 和导出库的内存表现。OPcache 缓存字节码，不能替代数据查询优化。

### 25. 如何证明一个 Laravel 报工接口可以上线？

**参考回答：** 除正常提交外，验证无权限、跨工厂、重复请求、同键不同内容、超量报工、库存竞争、事务回滚、队列重复执行和外部超时。检查报工、库存流水、审计、outbox 的一致性，并在接近真实数据规模的环境观察耗时、锁等待和错误率。

**追问要点：** 使用框架 HTTP Fake 测外部故障，但行锁和死锁应使用与生产相近的 MySQL 环境验证；不能用 SQLite 通过的测试推断 MySQL 并发行为。

### 26. 项目能在 PHP 8.2 上运行, 就说明版本选型没有问题吗?

**参考回答:** 不说明. 兼容性回答能否运行, 维护周期回答还能获得什么修复. 根据上述官方日期, 应分别检查 PHP、Laravel、扩展和依赖包的支持状态, 用锁文件复现依赖, 在目标 PHP 环境检查平台依赖, 再回归登录、事务、序列化、队列和导出. 不在生产环境直接执行全量依赖升级. [L1][L1] [L2][L2]

**追问要点:** 升级前记录当前版本、弃用项、插件兼容性和回退条件. 没有实际项目锁文件时只能说明评估方法, 不能声称已经验证升级兼容.

### 27. ERP 返回 HTTP 500, Laravel 为什么可能没有进入 `catch`?

**参考回答:** 普通 Laravel HTTP Client 请求收到 4xx/5xx 时默认返回响应对象, 可用 `successful()`、`failed()` 判断, 或显式 `throw()` 将相应响应转换为异常. 连接失败与响应错误还需分开处理. 业务返回 HTTP 200 但单据被拒绝时, 仍要验证业务码、结构和最终单号. `retry()` 有自己的重试和异常行为, 不能把普通请求的默认行为不加区分地套过去. [L3][L3]

**场景追问:** 用 Fake 分别构造连接失败、500、200 + 业务拒绝、202 + 处理中. 每种情况明确同步状态、可否重试、日志和查询入口, 避免把“收到响应”写成“ERP 已入账”.

### 28. `ShouldBeUnique` 与 `WithoutOverlapping` 的控制边界有什么不同?

**参考回答:** 前者在派发阶段使用唯一任务锁抑制重复入队; 后者是执行阶段的互斥中间件. 两个不同 Job 类即使给 `WithoutOverlapping` 相同键, 默认也不跨类互斥, 需要按业务评估 `shared()`. 这些都不是数据库业务幂等的替代品. [L4][L4]

**追问要点:** 锁过期早于实际执行结束可能重新出现并发; 无法取得锁后释放回队列也会消耗尝试次数. 验证共享缓存、锁期限、重试预算与 worker 崩溃恢复, 不机械复制默认值.

### 29. 改成 Octane 后, 为什么可能出现 A 工厂看到 B 工厂上下文?

**参考回答:** 常驻 worker 复用应用对象. 若在单例构造时捕获当前请求、用户或租户, 后续请求可能继续读取旧上下文. 应将请求相关值显式传入业务方法, 或使用适合生命周期的绑定, 避免静态变量积累请求状态. Laravel 的 `scoped` 绑定会在新的请求或 Job 生命周期清理实例, 但不能清除业务代码自行保存的全部全局引用. [L5][L5] [L6][L6]

**场景追问:** 在同一个 worker 上交替执行两个组织的请求与任务, 检查查询条件、缓存键、日志上下文及附件授权. 单请求测试通过不能证明常驻隔离正确.

### 30. 批量把待同步记录改成已同步, 为什么用 `chunk()` 可能漏数据?

**参考回答:** 基于偏移量分页时, 已处理记录退出筛选集合, 后续偏移可能跳过尚未处理的数据. Laravel 文档建议边遍历边更新时采用 `chunkById()` 等稳定主键推进方式, 同时不要修改推进键; 组合 `orWhere` 时需对条件分组. [L7][L7]

**追问要点:** 主键推进不是一致性快照. 若旧记录会重新变成待处理, 还需下一轮扫描或独立领取状态机. 验证中断续跑、同记录重复处理和并发状态变更, 分批大小依据实测内存与锁时间确定.

## 五、把一次报工讲成完整实现

**教学场景：** A 工厂员工提交一次报工，客户端请求键为 `report-001`，本次消耗 3 件物料。目标是“重试不重复扣料、越权不落库、同步失败可恢复”。

1. **入口校验：** 认证身份，校验数量、字段和请求键；通过 Policy 等现有授权入口确认工厂与工单权限。格式合法不等于业务允许。
2. **本地事务：** 按约定顺序锁定或条件更新相关记录，校验当前状态；用有明确作用域的唯一键登记操作，并保存报工、扣料、流水、关键审计及必要的 Outbox 事件。任一步失败则回滚这些本地写入。
3. **重复处理：** 相同键、相同规范化业务内容返回已有结果；相同键、不同数量返回冲突。重复键异常发生后，先退出失败事务，再通过可读取已提交结果的路径查询原操作，并重新校验访问权限。
4. **异步同步：** worker 使用稳定来源单号对接 ERP，分别记录本地提交与远端确认状态。外部超时进入结果查询或受控重试，不能再次执行本地扣料。

::: tip 特别解释：认证、授权、校验是三道不同的判断
**认证（Authentication）**回答“你是谁”；**授权（Authorization）**回答“你能否对这张工单执行报工”；**校验（Validation）**回答“提交内容和当前业务条件是否允许”。登录成功、数量是正数，都不能证明员工可以操作另一个工厂。
:::

**自测与预期：** 连续及并发提交两次 `report-001`，都只能形成一笔报工和一次 3 件扣料；改为同键消耗 4 件应冲突；ERP 超时后本地记录仍可查，补发不增加本地消耗。以上是验收设计，不是已执行的测试结果。

## 关键术语与专业解释

下列定义为官方概念的中文概括; 场景建议是工程推导, 不是框架的绝对保证.

| 术语 | 专业解释 | 容易混淆的边界 |
| --- | --- | --- |
| DI / Dependency Injection, 依赖注入 | 从对象外部提供其协作依赖, 容器可解析构造依赖和绑定 | 不等于必须为每个类创建接口. [L6][L6] |
| IoC Container, 控制反转容器 | 管理依赖的注册、解析和对象生命周期 | 容器是实现 DI 的机制, 业务事务仍需显式设计. [L6][L6] |
| Singleton / Scoped | 前者复用绑定实例, 后者限定在 Laravel 请求或 Job 生命周期内复用 | 常驻进程的单例不等于“一次 HTTP 请求一个实例”. [L6][L6] |
| PSR-4 | PHP-FIG 制定的类自动加载规范, 将命名空间前缀与目录关联 | 类名、子命名空间与文件路径的大小写要匹配, 不是 Composer 的依赖版本算法. [L8][L8] |
| Job / Worker | Job 表达待执行工作, worker 负责从队列获取并执行工作 | 派发成功、执行成功、外部业务成功是不同状态. [L4][L4] |
| `after_commit` | 把相关排队工作的派发推迟到开放事务提交之后 | 不能原子保证数据库提交与外部 broker 入队一起成功. [L4][L4] |
| Atomic Lock, 原子锁 | 用不可分割的获取操作协调互斥访问 | 锁超时、共享后端和崩溃恢复决定实际有效范围. [L4][L4] |
| Chunk / Cursor Pagination | 按批次处理结果与按稳定排序键推进是不同维度 | 分批并不自动提供快照, `chunkById()` 也不是任意跳页. [L7][L7] |

### 基础关键词补充：先理解，再记缩写

| 关键词 | 通俗解释与本篇场景 | 必须区分的概念 |
| --- | --- | --- |
| JD（Job Description） | 岗位说明；本系列据此选择制造业务与开发问题 | 题库准备不等于真实项目经历 |
| ORM（Object-Relational Mapping） | 对象关系映射；Eloquent 用模型和关联表达数据库操作 | 写模型代码仍会执行 SQL，仍有锁、查询量和事务成本 |
| N+1 查询 | 查询一次列表，再为每条记录单独查关联；100 条工单可能产生 101 次查询 | 是查询次数问题，不是返回了 101 行；实际次数取决于关联访问 |
| Middleware / Policy | 中间件处理请求链路的共同约束，策略类集中表达资源动作授权 | 前端按钮可见性不能替代服务端授权 |
| Mass Assignment（批量赋值） | 将一组输入字段写入模型，如 `create()`、`fill()` | `$fillable` 限制可批量写的字段，不自动验证工厂归属 |
| COW（Copy-on-Write，写时复制） | PHP 数组可先共享底层存储，需要修改时再分离 | 不等于引用，也不是多个进程之间的同步机制 |
| PHP-FPM / OPcache | 前者管理处理 PHP 请求的工作进程，后者缓存编译后的字节码 | 字节码缓存不缓存工单查询结果 |
| SQL 注入 / XSS / CSRF | 分别涉及输入改变 SQL 意图、在页面执行恶意脚本、借用户自动携带的凭证伪造请求 | 参数绑定、上下文转义、CSRF 防护各有目标，不能互相替代 |
