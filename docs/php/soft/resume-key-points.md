
### ⭐ 项目经验优先级排序

**建议结构**：

```markdown
最近工作（最重要）→ 前一份工作 → 早期经历 → 个人项目
```

**每个项目必须包含**：

1. 项目名称 + 规模（多少人团队、多少用户量）
2. 你的角色（独立负责 / 核心开发 / 参与）
3. 技术栈（Laravel 版本、MySQL 类型等）
4. **关键成果量化**（性能提升 XX%、节省 XX 成本、支撑 XX 用户）
5. 难点与解决方案（最多 3 个亮点）

```php
class Resume {
    function work() {  // ❌ 缺少类型声明
        echo "工作经验";
    }
```

```php
class ProjectExperience {
    public function createOrder(array $data): Order {
```

## 量化业绩的黄金法则

### ✅ STAR 原则

**Situation（情境）** → Task（任务） → Action（行动） → Result（结果）

```markdown
Bad: "我优化了数据库查询性能"

Good: "面对每月 10 万订单量增长带来的性能瓶颈（S），
需要将报表导出时间控制在 30 秒内（T）。
我通过 EXPLAIN 分析慢查询，建立复合索引，
并使用 Redis 缓存热点数据（A）。
最终报表响应时间从 45 秒降低到 18 秒，
服务器 CPU 负载下降 60%（R）。"
```

### ✅ 量化维度

```markdown
可量化的指标：
• 性能：响应时间从 X 秒降到 Y 秒
• 吞吐量：QPS 从 X 提升到Y
• 成本：服务器费用节省 XX 元/月
• 用户：支撑用户数 XX 万、日活 XX 万
• 效率：开发效率提升 XX%、bug 率降低XX%
• 规模：年交易额 XX 亿、订单量 XX 万单
• 质量：系统可用性 99.9%、数据准确率 100%
```

## 最后的黄金法则

### ✅ Do's（应该做）

1. **一页纸原则**：除非超过 10 年经验，否则尽量压缩到一页
2. **STAR 原则**：用情境 - 任务 - 行动 - 结果描述项目
3. **数据说话**：尽可能量化成果
4. **针对岗位**：每次投递前微调关键词
5. **真实可信**：不要编造，面试很容易露馅

### ❌ Don'ts（不应该做）

1. 写满 5 段自我评价废话
2. 列出不会的技术名称
3. 出现拼写错误、错别字
4. 格式混乱、排版不统一
5. 过于谦虚或过度吹嘘
