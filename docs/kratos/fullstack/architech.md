## 使用技术栈

### 前端

- Typescript，原生 JS-ES6
- CSS3
- Vue3
- Vite
- Element Plus
- Uni-App



### 后端

- Go
- gin
- gorm
- MySQL
- redis
- docker



## 目标

0 起点：全栈闭环开发一套通用的权限管理系统(`casbin`实现)，一个即时聊天模块，以及落地一个包含 PC 管理端和 uni-app 移动端的社交交友平台

### 前端

- 通过原生 JS+H5 写一个仿微信聊天交互界面
- 搭建前端开发结构以及封装常用工具方法以及 UI 组件(Ajax 请求、国际化支持、一键换肤、通用表格、通用表单、echarts 图表组件、EL 二次封装弹窗、抽屉等)
- 基于 Vue3+Vite+ElementPlus 开发通用权限管理系统（用户、部门、角色、权限/权限分类、字典、日志等模块）
- 整合前面基于 JS 以及 H5 实现的聊天界面，开发聊天相关的功能
- 在基础结构的上面开发社交/交友平台 PC 管理端（会员、红娘、实名认证、内容审核、牵线、投诉、工单等管理控制的实现）
- 基于 uni-app 开发社交交友 平台移动端（首页、动态页、即时消息页、个人中心页面、完善个人信息、提交实名认证、发起牵线、上传个人照片、发表动态、查看会员/动态/牵线/相册详情等）

### 后端

- 后端基础结构以及工具方法构建
- 基础结构上开发通用模块 RestFul API 的视线
- 开发社交交友平台后端的 API 接口实现
- 基于 docker 部署前后端



> 项目架构

```
用户通过【PC 浏览器、移动端浏览器、微信小程序】通过 Nginx 访问到前端应用【PC 端管理应用、uni-app 移动端 H5 应用】
通过后端路由然后到中间件 【跨域支持、Token 鉴权、权限控制、日志记录等】
分别与通用权限管理服务、即时聊天服务、社交交友服务进行数据交流；最后数据服务使用 go-redis->redis、gorm->mysql；
最后整体使用  docker 进行容器化处理。
```



> 跨端应用协作方式

- PC 管理端：Vue3+Vite+TS+ElementPlus，负责权限、后台管理业务
- 移动端：uni-app 负责移动端业务与交互，复用同一套后端 API 体系
- 共同点：统一登录态 Token、统一错误处理、统一接口约定
- 静态资源：前端 build 后交给 nginx 托管；运行时与后端 API 交互



> 后端服务分层与路由分组

- 分层：Controller API->service 业务->Dao 数据访问->Model/DTO/VO
- 路由分组：Public(/api/pub)、Auth(/api 仅登录)、Perm(/api 登录+权限)
- Swagger：统一接口文档入口，便于前后端联调
- 优雅启停：信号监听+Shutdown，保证服务可控退出



> 中间件链路

- CORS：允许前端跨域访问
- Token 鉴权：解析 Token，校验有效性；可做续期、刷新（响应头下发新 token）
- 权限控制价（casbin-RBAC）：基于角色的访问控制，按“用户、角色、资源、方法”判断，失败返回 403
- 操作审计：记录关键操作（谁在何时对什么做了什么），便于追踪



> 即时消息

- api：联系人列表、历史消息、未读数、设置已读等可追溯数据
- websocket：实时推送消息与回执，提示聊天体验
- 典型链路：发送消息->落库->返回成功->WS推送给对方在线客户端



> 资源存储分工

- MYSQL：持久化业务数据（用户、角色、权限、消息、业务模块数据等）
- redis：token、会话与热点缓存；提升鉴权与列表接口的性能
- 资源存储：附件、头像、图片等。通过 `/res` 统一对外访问
- 关键点：数据一致性（未读数、消息状态）与安全（上传大小、路径、鉴权）
